# Positioning

This guide is for teams comparing agent protocol work. You will learn how ABP relates to neighboring protocols and projects.

These short descriptions summarize the positioning in [protocol section 19](../spec/protocol.md#19-positioning-protocol-neighbors-informative). They are not mappings or conformance claims.

- **A2A** defines agent-to-agent task and message exchange.
- **MCP** defines client-server access to tools and data.
- **Agentic Resource Discovery (ARD)** proposes discovery and search for agentic resources.
- **AI Catalog** covers discovery, verifiable identity, and attestation.
- **SCITT** defines transparent publication and verification of supply-chain statements.
- **in-toto** provides a framework for describing and checking software supply-chain steps.
- **SLSA** describes security requirements through software supply-chain levels.
- **OASF** is an open schema framework for agent metadata.
- **WIMSE** addresses workload identity across systems.
- **AuthZEN** addresses authorization interoperability.
- **AP2** defines an agent payments protocol.

ABP defines portable capability and deployment artifacts, bounded verification, and conformance cases. It complements transport, discovery, identity, authorization, payment, and supply-chain projects.
